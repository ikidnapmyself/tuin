# `tuin` v0.1.0 — Design

**Date:** 2026-06-06
**Status:** Approved; this is the design of record for the initial public release.
**Target version:** `v0.1.0`
**Repo:** `https://github.com/ikidnapmyself/tuin`

This document is the single design of record for `tuin`'s first public release.
It consolidates the project's earlier per-feature design notes (the bootstrap
primitives, the safety guards, the cascading-menu primitive, the agentic docs,
and the supply-chain trust model) into one coherent description of everything
that ships in `v0.1.0`. The user-facing contract lives in
[`README.md`](../../README.md); the agent-facing distillation lives in
[`AGENTS.md`](../../AGENTS.md). This file holds the rationale, the locked
decisions, and the implementation order.

The full feature set was developed iteratively before the repository was made
public. Because nothing had shipped under a tag yet, the entire surface is
released honestly as one initial `0.1.0` rather than as a fabricated version
history.

---

## 1. What we are building

`tuin` (Dutch for "garden"; symbol: tulip) is a single-file, zero-dependency,
MIT-licensed pure-bash TUI primitives library targeting bash 3.2+. It gives
bash scripts drop-in replacements for `select`, `read -p`, and ad-hoc y/n
prompts — plus a spinner, styled banners, and two safety guards — with graceful
fallbacks on non-TTY pipes, CI, and `TERM=dumb`.

Distribution is one file: `tuin.sh`. Consumers `source` it. The whole value
proposition is "a zero-overhead tool to have": no runtime, no build step, no
supply chain to audit, nothing to keep updated.

Nine public functions:

| Function | Purpose |
|---|---|
| `tuin_choose` | Arrow-key menu (type-ahead filter at ≥10 items). |
| `tuin_menu` | Looping ("never-dying") menu for cascading drill-down interfaces. |
| `tuin_confirm` | Single-keypress y/n with default. |
| `tuin_input` | Read a line with default + optional regex validation. |
| `tuin_spin` | Animated spinner wrapping a foreground command. |
| `tuin_banner` | Boxed banner (Unicode / ASCII). |
| `tuin_section` | Section divider. |
| `tuin_unpriv` | Refuse a privileged (root / sudo) launch. |
| `tuin_guard` | Screen a command's `argv[0]` for privilege escalation. |
| `tuin_version` | Print the loaded library version. |

## 2. Positioning

tuin is a polished bash helper for **shell-first / ops contexts** —
language-agnostic shell glue. Its niche is the shell-first middle:
nicer-than-`read` interaction with zero install, running wherever bash does.
Target contexts: installers, VPS/bootstrap provisioning, CI glue, ops runbooks,
and multi-language environments where no richer runtime can be assumed.

tuin is **not** meant to compete inside richer runtimes. If you are already in
Python, use `questionary` / `rich`; for full-screen/mouse UIs, use an
ncurses-based framework. Docs frame tuin around shell-first/ops value and are
honest about when not to reach for it.

The library is the zero-dependency substrate for building **native** CLI
wrappers — for example a `manage.py`- or `artisan`-style front-end, or an ops
menu — that a team vendors as one file with nothing to maintain.

## 3. Locked decisions

| Item | Value | Rationale |
|---|---|---|
| Library filename | `tuin.sh` | Project-name consistency. |
| Public API prefix | `tuin_*` | Project-name consistency. |
| Private prefix | `_tuin_*` | Project-name consistency. |
| Load-guard | `_TUIN_LOADED` | Prevents collisions / double-definition on idempotent `source`. |
| Color vars | `_TUIN_CYAN`, `_TUIN_BOLD`, `_TUIN_REV`, `_TUIN_RESET` | Underscore prefix avoids shadowing a caller's `CYAN`, `BOLD`, etc. |
| Sole public global | `$TUIN_REPLY` | Written only when `tuin_menu` picks an action; nothing leaks at source time. |
| Menu Back-label knob | `TUIN_MENU_BACK` | Lets callers relabel the auto-appended Back entry. |
| Copyright holder | `Burak` | Owner preference (first name only). |
| License | MIT | Unencumbered redistribution; matches the niche. |
| Initial version | `0.1.0` | Honest pre-1.0 for an unproven API; reserves `1.0.0` for "API stable, real-world validation". |
| Guard failure signalling | `return` non-zero, never `exit` | A sourced lib that `exit`s kills interactive shells and can't be unit-tested. `|| exit` gives callers the "gently exit" behavior. |
| Root detection | `$EUID` via a private `_tuin_euid` seam | Pure bash — no `id` external. The seam lets tests simulate root by redefining `_tuin_euid`. |
| Sudo detection | `SUDO_USER` / `SUDO_UID` set | Catches `sudo` even to a non-root target. |
| Escalation denylist | `sudo doas su pkexec run0 sudoedit` | Common privilege-escalation entry points. |
| Guard screen scope | basename of `argv[0]` only | Catches the direct/accidental case; deliberate obfuscation is out of scope (documented). |

## 4. Design constraints

1. **Zero runtime dependencies** beyond `bash` (3.2+), `printf`, `read`,
   `stty`, `tput` — all POSIX or standard.
2. **Single file** — `tuin.sh` is the entire library. No internal split.
3. **MIT licensed** — full text in `LICENSE` and as a preamble in `tuin.sh`.
4. **TTY-aware** — every primitive degrades on pipes, CI, `TERM=dumb`, or unset
   `TERM`. `tuin_choose` / `tuin_menu` draw their UI on `/dev/tty` (see §9); the
   others check `[[ -t 1 && -t 0 ]]`.
5. **`NO_COLOR` compliant** — respects no-color.org; emits zero ANSI escapes
   when `NO_COLOR` is set.
6. **UTF-8 aware** — detect via `LC_ALL` / `LC_CTYPE` / `LANG`; ASCII fallback
   for decorations. Labels stay ASCII regardless — tuin has no localization.
7. **Cleanup-safe** — restore cursor + `stty` on SIGINT, SIGTERM, normal exit.
   Idempotent.
8. **Bash 3.2 compatible** — macOS's default shell. No bash-4+ features.
9. **Idempotent sourcing** — `_TUIN_LOADED` guard.
10. **Namespaced** — public `tuin_*`, internal `_tuin_*`. No side-effect globals
    leak; `$TUIN_REPLY` is the only public global, set only by `tuin_menu`.

## 6. Bash 3.2 compatibility cheatsheet

macOS still ships bash 3.2. The implementation targets it.

| Bash 4+ feature | 3.2 alternative |
|---|---|
| `${var,,}` / `${var^^}` (case folding) | `shopt -s nocasematch` with `[[ ]]` |
| `mapfile` / `readarray` | `while IFS= read -r line; do …; done` |
| `declare -A` (associative arrays) | Parallel indexed arrays |
| `local -n` (namerefs) | A documented global (`$TUIN_REPLY`) |
| `read -t 0.5` (fractional seconds) | `read -t 1` (integer seconds only on 3.2) |
| `&>` redirect | `>file 2>&1` |
| `printf -v var …` | Works in 3.2 — fine |

Concrete note: for `tuin_choose`'s ESC-sequence detection, bash 3.2 only
supports **integer-second** timeouts on `read -t`. `read -t 0` is NOT a polling
mode on 3.2 — it returns failure immediately without consuming buffered bytes
(the peek/poll semantics arrived in bash 4.0). The smallest practical grain is
`read -rsn2 -t 1 seq`: an arrow key's trailing bytes are already buffered when
this fires, so they're consumed immediately, while a bare ESC press takes ~1s to
time out and register as cancel. A future bash-4+ build can drop to `-t 0.05`
for a snappier ESC.

## 7. Per-primitive algorithm sketches

### 7.1 `tuin_choose` (the load-bearing primitive)

```
1. Validate: at least 1 option, else return 2.
2. Interactivity check (_tuin_choose_tty): need stdin a TTY AND /dev/tty
   openable r+w AND TERM sane. Otherwise:
     Fallback path. Read one line from stdin.
       Parses as 1-indexed integer in range → print that option.
       Otherwise → print first option.  Return 0.
3. Interactive path (all UI via /dev/tty; see §9):
     a. saved_stty=$(stty -g); cbreak + no-echo; hide cursor; install trap.
     b. filter_enabled = (item_count ≥ 10)
     c. Render list, highlight selected (default index 0).
     d. read -rsn1 loop:
          up/down: move selection (clamped)
          Enter:   print items[selected] to stdout, return 0
          Backspace: pop filter char (if filter on), re-filter, re-render
          printable: append to filter (if filter on), re-filter, re-render
          ESC alone: cleanup, return 1
          Ctrl-C (trap): cleanup, return 130
     e. Redraw: move cursor up by last frame height, clear, reprint.
     f. Cleanup: show cursor, restore stty, untrap.
```

`_tuin_choose_filter` is hoisted to module level so tests can invoke it
directly: `_tuin_choose_filter <filter> <item…>` prints matching 0-indexed
indices. Filtering uses `shopt -s nocasematch` for case-insensitive substring
match; `selected` is clamped into the filtered range on every change.

### 7.2 `tuin_menu <title> <opt1> [opt2 …]`

A thin loop over `tuin_choose` that makes cascading + never-dying menus fall out
of composition. **Not** a declarative menu engine — the caller still writes
their own `case` dispatch.

```
1. options = ("$@" + Back)        # Back label = ${TUIN_MENU_BACK:-Back}
2. Interactive: sel = tuin_choose over options; rc = its return code.
   Non-interactive: read one numbered choice from stdin;
     EOF / empty → return non-zero (loop must terminate on a closed pipe).
3. sel == Back, or rc is ESC(1)/Ctrl-C(130) → return non-zero (ends the loop).
4. Otherwise: TUIN_REPLY="$sel"; return 0  (loop continues → never-dying).
```

Return value travels via the `$TUIN_REPLY` global, not a nameref (bash 3.2 has
no `local -n`) and not command substitution (that would re-enter a subshell;
the loop body must run in the current shell). Cascading is just nesting: a
submenu is a function with its own `tuin_menu` loop; selecting Back returns
control to the parent. No state stack or breadcrumbs in core — a caller wanting
breadcrumbs passes its own `<title>` (e.g. `"Main > Health"`).

### 7.3 `tuin_confirm`, `tuin_input`

`tuin_confirm`: indicator `[Y/n]`/`[y/N]` per default; single `read -rsn1`;
`y/Y`→0, `n/N`→1, empty→default. Non-TTY: read stdin, leading `y` → 0, empty →
default, else 1.

`tuin_input`: prompt with `[default]` if set; loop `read -r`; empty → default;
if regex empty or value matches → print to stdout and return; else print a hint
to **stderr** and reprompt (stdout stays clean for capture). Non-TTY: read one
line, fall back to default if empty, ignore the regex (pipe callers pass valid
input).

### 7.4 `tuin_spin <label> -- <cmd …>`

Parse `label`, require the `--` separator (so the label may contain spaces),
run `"$@"` in the background, animate frames (`⠋⠙⠹…` UTF-8 / `|/-\` ASCII) while
it lives, then `wait` and return its exit code. The inner command's stdout/stderr
pass through unchanged. Non-TTY: `exec "$@"` / run directly with no animation.

### 7.5 `tuin_banner`, `tuin_section`

`printf` wrapping a title in box-drawing (`╔ ═ ║ ╝`) or `+ - |` ASCII, and a
`═══ heading ═══` / `=== heading ===` divider. UTF-8 vs ASCII chosen via
`_tuin_is_utf8`; color via the private `_TUIN_CYAN` / `_TUIN_RESET` vars.

### 7.6 `tuin_unpriv` — require an unprivileged launch

```
If root (_tuin_euid == 0) OR under sudo (SUDO_USER / SUDO_UID set):
    print a one-line notice to stderr (plain ASCII); return non-zero.
Else: return 0, silent.
```

Idiom: `tuin_unpriv || exit 1`. Root detection reads `$EUID` through the
one-line private `_tuin_euid` seam (pure bash, no `id`), which a test redefines
to report `0` to exercise the root branch.

### 7.7 `tuin_guard <cmd> [args …]` — screen for escalation

```
$# == 0                      → notice to stderr; return non-zero (caller error)
basename "$1" in
  sudo|doas|su|pkexec|run0|sudoedit → notice to stderr; return non-zero
  *                          → return 0
```

Only `argv[0]` is inspected: `/usr/bin/sudo apt update` is caught (basename
`sudo`) while `echo sudo` is not (basename `echo`). An empty invocation fails
closed as a caller error. Idiom: `tuin_guard "$@" && tuin_spin "Running" -- "$@"`.

## 8. Color and locale detection

```bash
_tuin_is_tty()    { [[ -t 1 && -t 0 && -n "${TERM:-}" && "$TERM" != "dumb" ]]; }
_tuin_use_color() { _tuin_is_tty && [[ -z "${NO_COLOR:-}" ]]; }
_tuin_is_utf8() {
    case "${LC_ALL:-${LC_CTYPE:-${LANG:-}}}" in
        *[Uu][Tt][Ff]-8 | *[Uu][Tt][Ff]8) return 0 ;;
        *) return 1 ;;
    esac
}
```

When `_tuin_use_color` is true, the four `_TUIN_*` vars are populated (prefer
`tput`, raw ANSI fallback); otherwise they stay empty and `printf` emits plain
text. All four are private so they don't shadow a caller's `CYAN` / `BOLD` /
`RESET`. `_tuin_is_utf8` decides once at source time; primitives branch on it at
call time.

## 9. The `tuin_choose` I/O model (UI on `/dev/tty`)

`tuin_choose` separates its **UI stream** from its **result stream**, mirroring
how `fzf` / `gum` / `dialog` work:

| Concern | Stream |
|---|---|
| Menu render / cursor / redraw | `/dev/tty` |
| Key reads | `/dev/tty` |
| Selected value | stdout (fd 1) |
| "Interactive?" predicate | stdin a TTY **and** `/dev/tty` r+w **and** `TERM` sane |

This is what lets `choice=$(tuin_choose …)` show arrow keys **and** return the
value — capturing the result no longer disables the interactive UI. Keeping the
stdin-is-a-TTY requirement preserves the "piped stdin → numbered fallback"
behavior and keeps every non-TTY BATS test green (no `/dev/tty` under BATS).

A private helper (`_tuin_choose_tty`) resolves the device and the predicate so
the behavior is localized and testable; `_tuin_is_tty` is **not** globally
redefined (other primitives rely on its current meaning). Documented consequence:
`tuin_choose … | tee log` (piped stdout with a real keyboard) now runs
interactively instead of falling back — the correct behavior (matches `fzf`),
scoped to `tuin_choose` only.

## 10. Cleanup traps

```bash
saved_stty=$(stty -g)
stty -icanon -echo min 1 time 0 2>/dev/null
_cleanup() { printf '\033[?25h'; [[ -n "$saved_stty" ]] && stty "$saved_stty" 2>/dev/null; }
trap '_cleanup; trap - INT TERM; return 130' INT TERM
# …main loop…
_cleanup; trap - INT TERM
```

The trap fires on signals; function-end calls `_cleanup` explicitly. Double
cleanup is idempotent. Nested calls rely on call-stack semantics: an inner
`trap` overrides the outer; inner cleans up + returns 130, the outer loop sees
it and propagates. SIGTSTP / Ctrl-Z is not handled (documented limitation).

## 11. Safety guards — framing

A sourced bash library **cannot enforce** a security boundary: any caller can
skip a check, and `tuin_guard` only screens the command it is handed, not what
that command later spawns. So `tuin_unpriv` / `tuin_guard` are **safe-by-default
guard rails** — they prevent the *accidental* footgun (running the whole tool as
root, invoking `sudo` from inside a menu) and make intent legible. This is
documented honestly in the README so no one mistakes it for a sandbox. The
guards `return` non-zero and warn on stderr; the caller decides what to do.

Audit/command logging was considered and **dropped** to keep the surface
minimal; a `tuin_run` safe-runner was **rejected** as too much surface. Both can
be revisited only on real consumer demand.

## 12. Agentic docs

Ship one canonical agent-facing file plus two thin pointers so every assistant
entry point shares a single source of truth:

- **`AGENTS.md`** (canonical) — the agent-shaped distillation of the README:
  what/when, `source` + idempotence, an API-contract table (signature, return
  codes, stdout-vs-stderr-vs-`/dev/tty` per function), imperative gotchas,
  copy-paste snippets for the four common shapes, and anti-patterns.
- **`CLAUDE.md`** — a single `@AGENTS.md` import; zero content.
- **`GEMINI.md`** — a thin pointer to `AGENTS.md`; zero content.

**Source-of-truth rule:** each contract fact lives in exactly one prose
location. The README is the human reference; `AGENTS.md` is the agent-shaped
distillation of the same facts; `CLAUDE.md` / `GEMINI.md` hold none. When the
API changes, README + `AGENTS.md` are the two files to update, and the doc-drift
test guards against divergence.

Rejected/deferred (conflict with zero-dep / low-maintenance identity, revisit
only under real adoption pressure): an MCP server, a separate `llms.txt`, a
standalone `docs/` cookbook.

## 13. Supply-chain trust model

tuin is vendored — adopters copy the single file into their own tree and run it.
The trust model is described in the README as **four checkable links**, all
vendor-neutral (no organisation, repository, or host is named in shipped
material):

1. **Pin a version** — depend on a tagged release, never a moving branch.
2. **Pin a digest** — record the release's SHA-256 alongside the version.
3. **Verify on fetch, fail closed** — check the download before placing it; a
   mismatch installs nothing.
4. **Vendor + review** — commit the verified copy so any change to the file or
   the pinned values shows up in a diff.

Honest boundary: the digest protects the **download**; commit-and-review
protects the **tree** — different attackers, neither "safer storage" than the
other. A digest the adopter self-computes from the same download is
trust-on-first-use only, which is why tuin publishes the authoritative digest
out-of-band.

**Producer side:** `make checksum` prints `shasum -a 256 tuin.sh` (falls back to
`sha256sum` — both base-system, zero added deps). Each tagged release records
`<sha256>  tuin.sh` in its release notes **and** the CHANGELOG entry, on a
surface separate from the raw file. No digest is embedded inside `tuin.sh` (a
file cannot contain its own hash). `RELEASING.md` is the long-form checklist;
the `make release` target prints the short form so the digest step rides the
path maintainers already follow.

**Consumer side:** `examples/vendor.sh` is a ready-to-use, zero-dependency
(`curl` + `shasum`/`sha256sum`), bash 3.2-safe implementation. The adopter pins
three values (`TUIN_VERSION`, `TUIN_SHA256`, `TUIN_URL`); it fetches to a temp
file, verifies the SHA-256, and only then atomically `mv`s it into place. On a
mismatch it deletes the download and returns non-zero (fail closed). The README
never hardcodes a host — `TUIN_URL` is a value the adopter sets.

Out of scope (noted in the README as "the next tier if your threat model needs
it," not built): GPG/sigstore signing, sidecar `.sha256` files, transparency
logs / TUF.

## 14. Testing strategy

**Automated — BATS, all non-TTY** (fits CI unchanged):

- **Pure-helper tests** invoke module-level helpers directly: `_tuin_is_tty`
  (piped / `TERM=dumb`), `_tuin_is_utf8` (`LC_ALL` / `LANG` / `LC_ALL=C`),
  `_tuin_use_color` (`NO_COLOR`, non-TTY), `_tuin_choose_filter` (empty filter,
  case-insensitive match, no-match).
- **Non-TTY contract tests** verify each primitive's pipe behavior: `tuin_choose`
  empty-options→2, numbered pick, empty/out-of-range→first; `tuin_confirm`
  yes/no/default; `tuin_input` passthrough/default; `tuin_spin` rc propagation +
  no ANSI; `tuin_menu` numbered pick sets `$TUIN_REPLY`, Back / EOF / empty /
  out-of-range → non-zero, Back-entry rendered, `TUIN_MENU_BACK` override,
  loop terminates.
- **Guards** (`test_guards.bats`): `tuin_unpriv` normal/`SUDO_USER`/simulated-root;
  `tuin_guard` safe commands, every denylist entry, absolute-path basename match,
  `echo sudo`→0 (argv[0] boundary), empty invocation → non-zero.
- **Docs/supply-chain** (`test_docs.bats`): every public function is documented;
  `RELEASING.md` exists; README contains the vendoring section + the
  verifying-snippet markers (`checksum mismatch`, fail-closed). `make checksum`
  prints a 64-hex digest; `make release` references publishing it.
- **Vendor snippet** (`test_vendor.bats`): installs on digest match, fails closed
  on mismatch, accepts an uppercase pinned digest, fails closed on a missing
  destination dir.
- **Version** (`test_release.bats` / helpers): `tuin_version` asserts `0.1.0`.

**Manual — interactive checklist** (only a human with a real terminal can
verify): arrow navigation + Enter; Ctrl-C cleanup; type-ahead filter + backspace
on ≥10 items; ESC clears filter / cancels; single-keypress confirm; animated
spinner on a >1s command; `full_demo.sh` end-to-end; `NO_COLOR=1` emits no ANSI;
`TERM=dumb` falls back to plain text; `LC_ALL=C` uses ASCII; macOS bash 3.2
arrow keys + type-ahead.

**CI:** BATS on `ubuntu-latest` + `macos-latest`, plus `shellcheck` over
`tuin.sh`, `examples/*.sh`, and the test helper. A bash-3.2 Docker matrix is
deferred; 3.2 stays manually verified.

## 15. Out of scope for v0.1.0

| Feature | Why deferred |
|---|---|
| Single-Ctrl-C cancel of `tuin_choose` | Bash 3.2 auto-restarts `read` after a trap; cursor + stty restore on the first press, but a second Ctrl-C is needed to exit. Documented limitation. |
| ~1s ESC delay in `tuin_choose` | Bash 3.2 only has integer-second `read -t`. Documented limitation. |
| SIGTSTP / Ctrl-Z recovery | Edge case; documented limitation. |
| Mouse events | Bash + mouse is a rabbit hole. |
| Windowing for menus longer than the terminal | YAGNI; most callers ≤ 10 items. |
| Alternate-screen "fullscreen TUI" mode | Scope creep — tuin is primitives, not a framework. |
| Multi-select in `tuin_choose` | Defer until a real consumer needs it. |
| Async progress bars with passing-through output | `tuin_spin` covers the 80%. |
| Declarative menu trees / a menu engine | Framework territory — rejected. |
| Audit / command logging; `tuin_run` safe runner | Surface discipline — dropped / rejected. |
| Configurable color themes | `NO_COLOR` is the contract; theming is upstream. |
| Auto-completion in `tuin_input` | Different problem space. |
| i18n / localization of labels | The library has no labels — only decorations. |
| bash-3.2 CI Docker matrix | Deferred; 3.2 stays manually verified. |

## 16. Versioning

Semver via git tags (`v0.1.0`, `v1.0.0`, …). Each tag has a `CHANGELOG.md`
entry and a published `tuin.sh` SHA-256. A `tuin_version` function lets consumers
detect the loaded version at runtime. `1.0.0` is reserved for "API stable, real
-world validation."
