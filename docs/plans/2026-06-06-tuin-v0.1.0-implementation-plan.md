# `tuin` v0.1.0 — Implementation Plan

**Date:** 2026-06-06
**Design:** [`2026-06-06-tuin-v0.1.0-design.md`](2026-06-06-tuin-v0.1.0-design.md)
**Target version:** `v0.1.0`

This is the consolidated build order for everything that ships in `v0.1.0`. It
merges the project's earlier per-feature implementation plans (primitives,
safety guards, cascading menu, agentic docs, supply-chain trust model) into one
sequence. Steps are bottom-up by complexity; each lands with its non-TTY
contract tests so the suite stays green throughout.

The work is complete as of this release — this plan documents the order it was
built in and is the checklist a future re-baseline would follow.

## Phase 0 — Scaffold

1. Create `LICENSE` (MIT, copyright Burak), `CHANGELOG.md` (Keep-a-Changelog
   format), `.gitignore`, and a `Makefile` with targets `test`, `lint`,
   `checksum`, `release`, `clean`.
2. Vendor BATS under `tests/test_helper/` as pinned submodules — `bats-core`,
   `bats-support`, `bats-assert` (all MIT). Record the pins in
   `tests/README.md` and `.gitmodules`.
3. Write the `tuin.sh` skeleton: MIT preamble (full text), `# Version:` header,
   `_TUIN_VERSION`, API docstring, `_TUIN_LOADED` guard, the color/locale
   detection block (§8 of the design), empty function stubs.

## Phase 1 — Easy primitives

4. Implement `tuin_banner`, `tuin_section`, `tuin_confirm`. Land each with its
   non-TTY contract tests (`test_banner_section.bats`, `test_confirm.bats`):
   UTF-8 vs ASCII decoration, `NO_COLOR` emits no escapes, confirm
   yes/no/default paths.
5. Implement `tuin_input` (`test_input.bats`): non-TTY passthrough, empty →
   default, regex reprompt loop with the hint on **stderr** and stdout clean.
6. Implement `tuin_spin` (`test_spin.bats`): require the `--` separator; non-TTY
   pass-through; rc propagation; no ANSI on a pipe. Manually verify the animated
   path.

## Phase 2 — `tuin_choose` (load-bearing)

7. Implement in sub-steps, each tested before the next:
   - Hoist `_tuin_choose_filter`; test directly (empty filter, case-insensitive
     substring, no-match) in `test_choose_filter.bats`.
   - Non-TTY fallback (numbered pick, empty/out-of-range → first, empty-options
     → 2) in `test_choose.bats`.
   - `/dev/tty` I/O model (§9): route render, cursor, redraw, and `read -rsn1`
     through `/dev/tty` via the private `_tuin_choose_tty`; selected value stays
     on stdout. Do **not** redefine `_tuin_is_tty` globally. Add the regression
     guard that capture (`out=$(…)`) keeps the numbered fallback under a pipe.
   - Interactive render loop + type-ahead filter (≥10 items); manual sanity check.
   - Trap cleanup (§10) last.

## Phase 3 — `tuin_menu` (cascading / never-dying)

8. Implement `tuin_menu` as a thin loop over `tuin_choose` (§7.2): build options
   + auto-appended Back (`${TUIN_MENU_BACK:-Back}`); set `$TUIN_REPLY` and
   return 0 on an action pick; return non-zero on Back / ESC / Ctrl-C
   (interactive) or EOF / empty (piped). Tests (`test_menu.bats`): numbered pick
   sets `$TUIN_REPLY`, Back / EOF / empty / out-of-range → non-zero, Back entry
   rendered, `TUIN_MENU_BACK` override, loop terminates without spinning.

## Phase 4 — Safety guards

9. Implement `tuin_unpriv` (root via the `_tuin_euid` seam; sudo via
   `SUDO_USER`/`SUDO_UID`) and `tuin_guard` (basename of `argv[0]` against
   `sudo doas su pkexec run0 sudoedit`; empty invocation fails closed). Both
   `return` non-zero + notice on stderr; never `exit`. Tests
   (`test_guards.bats`): per §14 of the design.

## Phase 5 — Examples

10. One runnable example per primitive plus composed demos: `menu.sh`,
    `form.sh`, `progress.sh`, `full_demo.sh` (all six TUI primitives),
    `safe_wrapper.sh` (a native-CLI-style wrapper composing both guards with a
    menu + spinner), `cascading_menu.sh` (drill-down + never-dying). Each must
    run cleanly on Linux + macOS, with and without `NO_COLOR`. `examples/README.md`
    indexes them.

## Phase 6 — Agentic docs

11. Author `AGENTS.md` (canonical): what/when, `source` + idempotence, the
    API-contract table, imperative gotchas, the four copy-paste snippets, and
    anti-patterns. Add `CLAUDE.md` as a single `@AGENTS.md` import and `GEMINI.md`
    as a thin pointer — zero duplicated content.
12. Add the doc-drift guard (`test_docs.bats`): every public `tuin_*` function is
    documented; signatures/return codes in `AGENTS.md` match `tuin.sh`. Verify an
    agent reading only `AGENTS.md` can emit correct, CI-safe scripts for the four
    canonical shapes.

## Phase 7 — Supply-chain trust model

13. Add the README "Vendoring tuin safely" section (the four checkable links +
    the honest download-vs-tree boundary) and `examples/vendor.sh` (zero-dep,
    bash 3.2-safe, fail-closed, atomic temp→verify→`mv`).
14. Add the `make checksum` target (`shasum -a 256` → `sha256sum` fallback) and
    the digest-publishing step to the `make release` checklist; write
    `RELEASING.md` as the long-form checklist.
15. Extend the doc/vendor tests: `test_docs.bats` asserts `RELEASING.md` exists +
    README section + snippet markers (`checksum mismatch`, fail-closed);
    `test_vendor.bats` covers install-on-match, fail-closed-on-mismatch,
    uppercase-digest, missing-dest-dir.

## Phase 8 — CI

16. `.github/workflows/` runs the BATS suite on `ubuntu-latest` + `macos-latest`
    and `shellcheck` over `tuin.sh`, `examples/*.sh`, and the test helper.

## Phase 9 — Release v0.1.0

17. Confirm `_TUIN_VERSION` and the `# Version:` header read `0.1.0`, and the
    `tuin_version` assertion expects `0.1.0`.
18. Move `## [Unreleased]` into a single `## [0.1.0] - 2026-06-06` CHANGELOG
    entry covering the whole surface; reduce the compare-link footer to the
    `0.1.0` release tag.
19. `make test` (green), `make lint` (clean), `make checksum`; record the
    `<sha256>  tuin.sh` digest in the CHANGELOG entry and the release notes.
20. Single clean initial commit on `main`; `git tag -a v0.1.0 -m 'tuin v0.1.0'`;
    push `main` + tags; publish the release with the digest line in its body.

## Verification gate

- `make test` green (full suite, including doc + vendor guards).
- `make lint` clean.
- `make checksum` prints a 64-hex digest; the same value is in the CHANGELOG and
  release notes.
- Vendor snippet hand-run: a good file installs, a tampered file fails closed
  (non-zero, nothing written).
- Manual interactive checklist (design §14) spot-checked in a real terminal.
